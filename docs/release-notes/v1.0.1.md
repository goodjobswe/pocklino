# Pocklino 1.0.1

QR sharing now uses smaller, clearer codes and lets you slow down the sequence while the other phone is scanning.

## What changed

- Animated codes carry 240 payload characters per frame instead of 400; static codes have a lower density limit too.
- Black-on-white QR codes use stronger error correction, an exact square grid, and a clear border sized to the code.
- The **Sharing speed** slider sits directly below the animated QR, with **Slower** and **Faster** ends. It starts at one second per frame and adjusts from two seconds to 0.4 seconds.
- Changing speed preserves the current sequence and received pieces. Pause and manual next-frame controls remain available.
- Static codes have an **Enlarge code** action instead of a speed slider.
- The camera looks specifically for QR codes. The receiver shows how many pieces have arrived and keeps them across repeated loops.

## Install

**Android:** download `pocklino-v1.0.1.apk`, open it on your phone and allow installation from the browser or file manager if asked. Requires Android 6.0 or newer.

**Windows:** download `pocklino-v1.0.1-windows.zip`, extract the whole archive, then run `pocklino.exe`. Keep the DLLs and `data` folder beside it. The ZIP includes the Visual C++ runtime. Windows can display QR codes and receive files or pasted codes; camera scanning is available on Android.

This APK uses the repository's release signing key and the application ID `nu.goodjob.pocklino`. The original Android Preview 1 used `se.goodjob.pocklino`, so this installs alongside that preview. Export a backup from the old app and restore it in the new one before removing the old app. It updates the signed `nu.goodjob.pocklino` version 1.0.0 in place.

Use the new version on both devices for very large animated transfers (more than 224 pieces). Older codes and `.pocklino` files can still be received.

## Try this

Pass a long note, move the speed slider toward Slower, and check that the receiver continues from its existing piece count. Try pause/resume, manually advance a frame, and let missed frames return on the next loop. Enlarge a short note's static code and compare scanning at different distances.

Physical-phone scanning speed depends on the receiving camera, focus and lighting. This release is ready for that testing; automated checks do not establish reliability on every phone.

## Validation

Static analysis is clean and all 58 Flutter tests pass, including speed changes, small-phone layout, missed-frame recovery and camera close/reopen sequencing. Seven real-font screenshot cases cover day/evening phone and desktop sharing plus static enlargement. All 14 rendered QR crops decode to their expected payloads after the documented image-size normalization used by the bundled decoder.
